# Changelog

## Unreleased

- A Gemini section that does not come back is said as *The request to Gemini timed out*, not as a lost connection or a vague failure. Each section is sampled at one frame every two seconds, a call is given three minutes, a deadline the server reports is tried once, and a section that still does not finish is described again in two shorter pieces. If the video has already moved on when the first descriptions arrive, the one for the moment on screen is read (led by *Earlier:* when it is late) instead of staying silent.
- **Nothing to install: a web player.** `site/play/` (https://reddynb666.github.io/scenevoice/play/, Chinese at `?lang=zh-CN`) is a page that takes a YouTube link and reads AI audio description in the browser, through the screen reader or the browser's own voice, in English or Simplified Chinese, with your own Gemini key (*SceneVoice Cloud* is on the page for when the relay opens). It is the phone path too. You hear the same things as in the extension: the AI notice before the first description, *You can start watching* after the first part, the percentages, *Descriptions ready*, descriptions in the pauses (the model's estimates, since the page has no captions), the same *Keep playing* / *Pause the video* / *Only when I ask* modes, detail and how-much controls, reading speed, repeat, describe now, ask a question with follow-ups, *Describe again*, and plain one-sentence errors with the resume hint when part of the video is saved. In a named player region (*SceneVoice player: press ? for the keys*) single keys drive it: Space, D, R, A, S, Left and Right (5 seconds), Up and Down (reading speed), M (mode) and ? (reads the list); `Alt+Shift+D`, `S`, `L` and `Q` work anywhere on the page and never in a text field. Status waits behind a description being read, and the live regions fall silent while the browser's voice speaks, so nothing is said twice. Bilibili links are refused with a pointer to the extension. Finished descriptions are cached in the browser (40 videos); the key stays in the tab's session storage unless *Remember the key on this device* is ticked, travels only in the `x-goog-api-key` header, and never reaches SceneVoice; YouTube's player is embedded from youtube-nocookie.com, loaded only on *Play*, and kept out of the Tab order. New *Web player* section in both privacy policies. For developers: `npm run build:web` writes `site/play/player.js` (not in git; the build fails if any `chrome.*` API gets in, and the Pages workflow builds it before the accessibility check and the upload); `site/check.mjs` now checks the player page too (axe WCAG 2.2 AA, live regions, every `data-i18n` key in both languages, the one external script named explicitly); the home pages link to it from the *Hear it* section; `scripts/locales.mjs` leaves the `web_*` strings out of the coverage count of the partial interface languages; `test/web-player.test.js` covers it.
- Web player: *Play* starts the video before asking the player for its length (the embedded player reports 0 until the video runs, so the page used to give up after ten seconds with *The length of the video is not known yet* on videos that never started); a failure to make descriptions is kept in view under the player and said again, with its reason, when D is pressed and there are none, instead of a bare *There are no descriptions for this video yet* after later status has talked over it.
- **Every command has a key, and the keys are changed inside SceneVoice.** Chrome lets an extension suggest only four shortcuts (`Alt+Shift+D` create or toggle, `Alt+Shift+S` describe now, `Alt+Shift+L` repeat, `Alt+Shift+Q` ask); the other commands used to start unset until the listener found chrome://extensions/shortcuts, a page that is hard to use with a screen reader. They now have keys handled on the video page itself, on YouTube and Bilibili alike: `Alt+Shift+W` marks the last description as wrong, `Alt+Shift+E` detail, `Alt+Shift+M` mode, `Alt+Shift+N` how much to describe, `Alt+Shift+Up` and `Alt+Shift+Down` faster and slower, `Alt+Shift+X` stop speaking, and a new `Alt+Shift+H` that reads every command with its current key in a few short sentences, after any description being read, even with status messages off. On a Mac the keys are said as "Option+Shift+…". Keys are matched by the physical key, so Option+Shift works although it types another character; they are ignored while typing in a field, a comment box, a search box or the ask dialog; a key SceneVoice handles never reaches the player, and a command that has a Chrome key is never handled twice. Settings page, *Keyboard shortcuts*: every command is listed with its key; the four Chrome keeps say so, with a button that opens Chrome's shortcuts page; the others have *Change* (press it, then the new combination, or Escape to keep the old one; the page says what was saved, refuses a key already used by another SceneVoice command or by one of Chrome's four, and needs Alt, Ctrl or Command with a letter, digit, arrow or function key), *Clear* and *Restore default keys*. The keys are a synced setting (`pageShortcuts`). The popup's *All keyboard shortcuts* list shows them too and its *Change shortcuts* button opens this section; the welcome page names `Alt+Shift+H`; every message that names a key (status, hints, next steps) uses the page key when Chrome has none; *Restore default settings* now also restores these keys (Chrome's four are untouched). New `src/shared/shortcuts.js` and `test/shortcuts.test.js`.

## 1.1.0 — 2026-11-04

- **No key needed to start (optional): SceneVoice Cloud.** A welcome page (`welcome.html`) opens after install with focus on its heading: *Hear a sample* reads three sample descriptions through your screen reader (or the built-in voice), then one choice: *Start free* or *I have my own key*. *Start free* asks the SceneVoice Cloud relay for an anonymous device token (no account, no e-mail), gives a free daily allowance of described minutes and has Cloud describe both sites; the allowance, plan, reset time, *Stop using Cloud* and a licence-key field for Plus or organisation plans live at the top of the settings page. A video someone with Cloud already had described is loaded from the shared cache instead of being made again (*Share finished descriptions*, on with Cloud, off otherwise; only finished description text is shared, never pictures, questions or your own key); used-up allowance says when it comes back. Users with their own key send nothing to SceneVoice; the key path is never degraded. New host permission `https://api.scenevoice.app/*`, justified in `PRIVACY.md` (new *SceneVoice Cloud* section) and `docs/store-listing.md`. The relay itself is a reference implementation under `server/` (Cloudflare Worker: devices, allowance, Gemini- and DashScope-compatible proxies that never store a request, script cache, licences, Stripe webhook, 47 tests, deployment and cost notes in `server/README.md`); it is not deployed yet, so *Start free* reports the failure plainly and points to the own-key path until it is.
- Descriptions keep out of the dialogue's way. A pause the model only estimated is now used with half a second of margin (a pause measured from captions is used in full), and the model is told never to invent a pause when it cannot tell. A description may only cut off one less important than itself; otherwise it is held for up to 5 seconds of video for a real pause, re-fitted at that moment, and dropped if none comes. A visual description that lands on speech waits up to 5 seconds for a pause its brief version fits at your reading speed. In *Keep playing* mode, after more than three descriptions have been skipped for want of a pause, SceneVoice says so once per video and names the shortcut that switches to *Pause the video*. In *Pause the video* mode with a screen reader the video is held 1.5 seconds longer before it resumes, so the last words are not lost. Jumping in the video stops the sentence being read. A description from pictures said more than 6 seconds after its moment begins *Earlier:* / *刚才：*, and very late ones are dropped. Each section's request carries the last four descriptions of the one before, so a section no longer re-describes the scene it opens in. The built-in voice waits for a hidden tab only when the video is silent too.
- What it costs, and a limit you set. A *Usage today* part of the settings page counts, per model (Gemini, Qwen, Cloud), the requests, tokens, minutes of video and an estimate in money, from a price table checked on 2026-11-04 (counted on this computer only, never sent anywhere); the popup says what the current video cost. A new *Daily limit* (none, 30 minutes, 1, 2 or 4 hours of described video) refuses new jobs for the rest of the day once reached and says so; asks and corrections still work, and nothing starts by itself again that day. Rate limits are told apart from used-up quotas: a minute's limit is retried after the wait the API asks for (at most 90 seconds), a day's quota switches once to another model family and is otherwise reported as such, and the Cloud allowance says when it resets. At most two picture requests per model are in flight at once; the rest queue in order.
- Any language. Descriptions can be written in any language the browser is set to, not only the ones with their own tables; twelve more languages have tables of their own (Italian, Dutch, Polish, Turkish, Vietnamese, Thai, Indonesian, Bengali, Urdu, Persian, Ukrainian, Swahili), with the hedging examples in the prompt built from the description language's own words. The live regions, the text shown on the video and the answer in the ask dialog carry the description language (and `dir="auto"`), so the screen reader switches voice; the popup says when the interface language and the description language differ; right-to-left language names are shown right to left. The video type is read from YouTube's numeric category id when the page has it, not only the name.

Besides English and Simplified Chinese, the interface is available in Traditional Chinese, Spanish, Portuguese (Brazil), French, German, Japanese, Korean, Russian, Arabic, Hindi, Indonesian and Vietnamese. The store name is now *SceneVoice: AI Audio Description for Video* (the old one did not fit the 45-character limit), and the summary names both sites in every language.

- Quiet moments stay quiet. Gemini is no longer asked for a description every 10 to 20 seconds: it describes only what is important and new, lets music, scenery and long takes play with a few words at a real change, and may return nothing for a section. *How much to describe* is now *Essentials only*, *Moderate* or *As much as possible* (*仅关键*, *适中*, *尽量多*), and follows the video type like mode and detail: entertainment describes only the essentials by default, and a density the user picks always wins (one saved by an earlier version that differs from the default counts as picked). Each type's density can be changed on the settings page; *Adjust mode and detail to the video type* is now *Adjust descriptions to the video type*.
- Mode and detail follow the video type. Entertainment (films, music, vlogs, games) keeps playing with brief descriptions; tutorials and explainers (lessons, how-to, science, news with charts) pause for detailed ones. The type comes from the YouTube category and title, read from the watch page SceneVoice already fetches for caption timing, and from Gemini, which now names the type in the same structured answer as the descriptions, so there is no extra request. It applies only to a mode or detail the user has not picked; a choice made in the popup, on the settings page or with a shortcut always wins (a mode or detail saved by an earlier version that differs from the default counts as picked). The page says once per video what changed and, the first time, how to change it back; the popup shows the values in use. On the settings page, *Adjust mode and detail to the video type* (on by default) turns it off, each type's mode and detail can be changed, and *Let the video type decide again* hands back a mode or detail the user picked. The video's type changes playback only; settings in storage are not touched, so tabs showing different videos do not affect each other.
- Descriptions no longer talk over dialogue. When the video has captions, their timing corrects the pauses the model estimated, and a description that starts at the tail of a sentence waits for it to end.
- In *Keep playing* mode a description that does not fit is now skipped, even an important one (previously its brief version was spoken anyway). In *Pause the video* mode it pauses the video instead.
- Built-in voice: pitch can now be set alongside voice and speaking rate. Voices for the description language are listed first (Chinese voices for Chinese descriptions), with their language spelled out, and each description language remembers its own voice. *Test voice* reads a sentence in the description language rather than the interface language. A synced voice that this computer does not have is replaced by an automatic voice for the description language.
- The popup has a speed control (built-in voice rate, or screen reader speed) next to detail and mode, a *Test voice* button, and names the shortcuts for these settings.
- New *Speak faster* and *Speak slower* shortcuts (unset by default, as Chrome allows only four suggested keys). Shortcuts that change a setting say the new value, and say so if it could not be saved.
- *Restore default settings* on the settings page. It keeps the API key, model, saved descriptions and keyboard shortcuts.
- Sliders are read out as values ("1.2×", "35%", "Normal") and are tied to their labels; the volume slider used to be read as "0.35", and the label around the rate and volume sliders belonged to the value shown next to them rather than to the slider.
- Settings are checked when read, so a bad or out-of-range value synced from another browser falls back to its default. Two quick changes on the same page no longer overwrite each other.

## 1.0.0 — 2026-10-29

First release.

- On-demand AI audio description for any public YouTube video, using your own Gemini API key.
- Three playback modes (keep playing, pause the video, only when asked) and three detail levels.
- Descriptions are written in three lengths and chosen to fit the pause at your reading speed and playback rate.
- On-screen text read as its own kind of cue.
- Output through screen reader live regions (default) or the browser's built-in voices.
- Describe now, repeat last, and an ask-a-question dialog.
- Videos are described in five-minute sections with partial results available early; progress is saved and resumes. Generation runs in a worker inside the extension's offscreen document (not in the YouTube page, whose connection allowlist would otherwise be able to block it, and not in the service worker, which Chrome stops after a 30-second fetch); tabs showing the same video share one job, and the job carries on if the tab leaves the video.
- Overloaded or missing models: retries with increasing pauses, then the next best model takes over automatically.
- English and Simplified Chinese interface; descriptions in twelve languages.
- Large-text overlay, player button, keyboard shortcuts, dark mode.
- Progress is visible (player pill, popup bar with Stop) and audible: pressing the SceneVoice button or `Alt+Shift+D` while descriptions are being created announces the percentage, the section being worked on and the time left.
- A "how much to describe" setting (essentials / standard / everything) filters cues by importance without regenerating; a transcript page lists every description with its timestamp.
- No server, no account, no analytics.
