# Changelog

## Unreleased

- The progress box is easier to see. It now sits just above the player's control bar (measured, so it clears the taller bar in fullscreen) instead of the top-left corner, where YouTube draws the video title in fullscreen; on Shorts, which have no control bar there, it stays at the top. Text is 16px (time left 15px) in white on near-black with a yellow border, and the box shows the percentage done. It attaches itself to the player if generation began before the player existed. It stays up while the controls hide and goes away when the descriptions are ready.
- **China site / Bilibili (experimental).** SceneVoice now also runs on Bilibili video pages (`www.bilibili.com/video/*`, top frame only), and can use Qwen (通义千问, through Alibaba Cloud Model Studio / DashScope's OpenAI-compatible API) as well as Gemini. The site and the model are two separate layers: a platform adapter per site (`src/content/youtube.js`, `src/content/bilibili.js`) and a provider per model (`src/shared/providers.js`, `qwen.js`, `describe.js`). The settings page has a model for each site (YouTube: Gemini by default; Bilibili: Qwen by default) and a Qwen key section, stored and kept from content scripts like the Gemini key. Gemini on YouTube works exactly as before. Any other combination is sent pictures instead of a link: the page takes a scaled-down frame of the playing `<video>` every 2 seconds and sends up to 6 per 12-second stretch; descriptions are added to the saved script, the newest important one is said at the next pause (a few seconds late), and the rest are heard on the next viewing. Questions and *Last description is wrong* send pictures of that moment. A video whose picture the browser protects (a cross-origin, "tainted" canvas) or that plays outside a `<video>` element gets a clear message instead. Bilibili's CC subtitles (written, then AI-generated) give the dialogue timing when they can be read; otherwise the model's estimate is used. On Bilibili, a description language that follows the browser means Chinese. Interface strings in English and Simplified Chinese. API details not yet confirmed are settings or constants marked 待确认 (see README).
- Fewer made-up details, and a way to correct the ones that remain. Gemini is now told to describe only what is visible: no guessed feelings or motives, no praise or judgement, and no names, jobs or relationships unless on-screen text or the dialogue gives them (the video title alone no longer counts), with wrong-and-right examples in English and Chinese. Blurred, small or partly read things are described as such ("appears to", "hard to see", "可能", "看不清"), and partly readable on-screen text is transcribed only as far as it can be read. Every description comes with a `confidence`; one marked low counts one step less important (so *Essentials only* leaves it out) and is led by "Not certain." / "不太确定。" (in the description language) unless its own words already say so. Scripts saved before this change keep working.
- Answers to questions say which moment they are about ("At 2:15: …", "在 2:15 处：…"), are based on the picture, and say so when Gemini is not sure. The recent descriptions sent with a question are marked as possibly wrong. Below the answer, *Go to 2:15* jumps there. Gemini now returns the answer as structured output (`time`, `confidence`, `answer`); a time it gives from the start of the clip is moved to the video, and one outside the clip is not trusted.
- *Last description is wrong* (popup button, and a new shortcut, unset by default) marks the description just heard, or the one for the moment on screen. Only that moment (about 20 seconds around it) is described again; the new description replaces the old one in the saved script, or the old one is removed if there is nothing there to describe. Each step is announced: what was marked, then the new words, or what went wrong. The marks are stored in the extension's local storage next to the script, re-applied when a generation still running saves a later section, and deleted with the script. The transcript page labels corrected descriptions.
- On-screen text comes first and is read word for word. Gemini now transcribes it in a field of its own (`onScreenText`), exactly as written, before writing the spoken versions, which quote it rather than paraphrase it; the instructions name what must not be missed (titles, names, slides, chart figures, prices, contact details, code, menus). Text gets one density step more than other descriptions, wins over a visual description of the same importance, is not cut off by a less important one, and, when it appears while someone is speaking, waits up to 8 seconds for a pause. When the video has captions, text that is also spoken within a few seconds (a slide read aloud, subtitles that match the captions) is left out. The transcript page shows the exact text where a description translates or shortens it. Scripts saved before this change keep working; create them again to get transcriptions.
- Quiet moments stay quiet. Gemini is no longer asked for a description every 10 to 20 seconds: it describes only what is important and new, lets music, scenery and long takes play with a few words at a real change, and may return nothing for a section. *How much to describe* is now *Essentials only*, *Moderate* or *As much as possible* (*仅关键*, *适中*, *尽量多*), and follows the video type like mode and detail: entertainment describes only the essentials by default, and a density the user picks always wins (one saved by an earlier version that differs from the default counts as picked). Each type's density can be changed on the settings page; *Adjust mode and detail to the video type* is now *Adjust descriptions to the video type*.
- Mode and detail follow the video type. Entertainment (films, music, vlogs, games) keeps playing with brief descriptions; tutorials and explainers (lessons, how-to, science, news with charts) pause for detailed ones. The type comes from the YouTube category and title, read from the watch page SceneVoice already fetches for caption timing, and from Gemini, which now names the type in the same structured answer as the descriptions, so there is no extra request. It applies only to a mode or detail the user has not picked; a choice made in the popup, on the settings page or with a shortcut always wins (a mode or detail saved by an earlier version that differs from the default counts as picked). The page says once per video what changed and, the first time, how to change it back; the popup shows the values in use. On the settings page, *Adjust mode and detail to the video type* (on by default) turns it off, each type's mode and detail can be changed, and *Let the video type decide again* hands back a mode or detail the user picked. The video's type changes playback only; settings in storage are not touched, so tabs showing different videos do not affect each other.
- Descriptions no longer talk over dialogue. When the video has captions, their timing corrects the pauses the model estimated, and a description that starts at the tail of a sentence waits for it to end.
- In *Keep playing* mode a description that does not fit is now skipped, even an important one (previously its brief version was spoken anyway). In *Pause the video* mode it pauses the video instead.
- Built-in voice: pitch can now be set alongside voice and speaking rate. Voices for the description language are listed first (Chinese voices for Chinese descriptions), with their language spelled out, and each description language remembers its own voice. *Test voice* reads a sentence in the description language rather than the interface language. A synced voice that this computer does not have is replaced by an automatic voice for the description language.
- The popup has a speed control (built-in voice rate, or screen reader speed) next to detail and mode, a *Test voice* button, and names the shortcuts for these settings.
- New *Speak faster* and *Speak slower* shortcuts (unset by default, as Chrome allows only four suggested keys). Shortcuts that change a setting say the new value, and say so if it could not be saved.
- *Restore default settings* on the settings page. It keeps the API key, model, saved descriptions and keyboard shortcuts.
- Sliders are read out as values ("1.2×", "35%", "Normal") and are tied to their labels; the volume slider used to be read as "0.35", and the label around the rate and volume sliders belonged to the value shown next to them rather than to the slider.
- Settings are checked when read, so a bad or out-of-range value synced from another browser falls back to its default. Two quick changes on the same page no longer overwrite each other.

## 1.0.0 — 2026-10-29

First release.

- On-demand AI audio description for any public YouTube video, using your own Gemini API key.
- Three playback modes (keep playing, pause the video, only when asked) and three detail levels.
- Descriptions are written in three lengths and chosen to fit the pause at your reading speed and playback rate.
- On-screen text read as its own kind of cue.
- Output through screen reader live regions (default) or the browser's built-in voices.
- Describe now, repeat last, and an ask-a-question dialog.
- Videos are described in five-minute sections with partial results available early; progress is saved and resumes. Generation runs in a worker inside the extension's offscreen document (not in the YouTube page, whose connection allowlist would otherwise be able to block it, and not in the service worker, which Chrome stops after a 30-second fetch); tabs showing the same video share one job, and the job carries on if the tab leaves the video.
- Overloaded or missing models: retries with increasing pauses, then the next best model takes over automatically.
- English and Simplified Chinese interface; descriptions in twelve languages.
- Large-text overlay, player button, keyboard shortcuts, dark mode.
- Progress is visible (player pill, popup bar with Stop) and audible: pressing the SceneVoice button or `Alt+Shift+D` while descriptions are being created announces the percentage, the section being worked on and the time left.
- A "how much to describe" setting (essentials / standard / everything) filters cues by importance without regenerating; a transcript page lists every description with its timestamp.
- No server, no account, no analytics.
