## Description

**EN**

SceneVoice adds audio description to any YouTube or Bilibili video. Press Alt+Shift+D, and within about half a minute per five minutes of video you hear what is on screen — who enters, what they do, what the signs and title cards say — spoken in the pauses between dialogue by your own screen reader.

Made for screen reader users
• Works with NVDA, JAWS and VoiceOver: descriptions go to a live region, so you keep your voice, speed and braille display.
• Every control works from the keyboard. Every state is announced.
• A built-in voice is available for listeners without a screen reader.

Fits the pauses
• Every moment is written in three lengths. SceneVoice picks the longest that fits the silence, at your reading speed and playback rate.
• Or let it pause the video and read the full description. Or stay silent until you ask.

Describe now, ask anything
• Alt+Shift+S describes the current moment at once.
• Alt+Shift+Q opens a dialog: "Who is speaking?" "What does the sign say?" and you get an answer about that exact moment.
• Alt+Shift+L repeats the last description.

Reads on-screen text first, word for word
• Titles, names, slides, chart figures, prices, contact details, code, menus and signs, exactly as written and before other descriptions, with translation when needed. Text you already hear is not repeated.
• Quiet moments stay quiet: nothing is described just to fill a silence.

Two sites, two models
• YouTube with Google Gemini, which reads the public video itself.
• Bilibili, or YouTube where Gemini is not available, with Qwen (Alibaba Cloud Model Studio), which is sent small pictures of the playing video. Qwen keys work inside mainland China.

Your key, your data
• You use your own API key: Gemini from Google AI Studio (free tier), or Qwen from Alibaba Cloud Model Studio. No account with us, no subscription, no analytics; with your own key, no server of ours is in the path.
• Or, optionally, SceneVoice Cloud: a free daily allowance without any key, through a relay that never stores pictures or questions. Your own key never passes through it.
• Descriptions are saved on your computer, so a video is described only once.

Languages
• Interface in 14 languages: English and Simplified Chinese, reviewed; Traditional Chinese, Spanish, Portuguese (Brazil), French, German, Japanese, Korean, Russian, Arabic, Hindi, Indonesian and Vietnamese, AI-drafted and awaiting native review.
• Descriptions in any language your browser is set to; 24 of them (English, Simplified and Traditional Chinese, Spanish, French, German, Portuguese, Japanese, Korean, Russian, Arabic, Hindi, Italian, Dutch, Polish, Turkish, Vietnamese, Thai, Indonesian, Bengali, Urdu, Persian, Ukrainian and Swahili) have their own hedging words and test sentences.

SceneVoice is free and open source (MIT). Descriptions are generated by an AI model and can be wrong; it is asked to say when it is unsure and never to invent names, and every run begins "AI-generated audio description follows."

## Permission justifications (for the review form)

- `storage`, `unlimitedStorage`: store the user's API key (or the SceneVoice Cloud device token), settings, usage counts and generated description scripts locally. Scripts for long videos can exceed the default quota.
- `tts`: optional built-in voice output for users without a screen reader.
- `activeTab`: lets the toolbar popup tell whether the current tab is a YouTube video and show the right status.
- `offscreen` (reason `WORKERS`): hosts the worker that sends the long video-description requests to the Gemini API. These take 30–90 seconds, longer than a service worker may wait for a fetch, and running them in the YouTube page would expose the user's API key to the page and subject the requests to YouTube's page policies.
- Host `https://generativelanguage.googleapis.com/*`: the Gemini API that generates descriptions.
- Host `https://dashscope.aliyuncs.com/*`: the Qwen API (Alibaba Cloud Model Studio), the model used on Bilibili and by users in mainland China, where Gemini is not available. Only called with the user's own Qwen key.
- Host `https://api.scenevoice.app/*`: SceneVoice Cloud, the optional relay for users without a key of their own. Called only after the user presses *Start free* or *Activate a licence key* (both issue an anonymous device token, no account; licence activation registers a device first if none exists); it forwards the same description requests to Gemini, keeps a daily count per token and, when the user leaves sharing on, the finished description text. Once a token exists, opening the settings page reads the plan and today's allowance from it (`GET /v1/me`), and starting descriptions first asks it for a finished script of that video (`GET /v1/scripts/…`) and, while sharing is on, offers the finished text back (`PUT`). Users with their own key never contact it.
- Content script on `youtube.com`: follow playback, show the player button, overlay and question dialog.
- Content script on `www.bilibili.com/video/*` (top frame only): the same on Bilibili video pages. It reads the page's own data and calls no Bilibili API.
- `all_frames: true` on the YouTube content script: YouTube videos are also watched inside embedded players (`youtube.com/embed`, `youtube-nocookie.com/embed`) on other sites, which are frames; the content script must run in that frame to follow the video and show the button. In a frame it never starts generation by itself; descriptions only begin after the viewer plays the video and presses the shortcut.
- Optional host permissions (`https://*/*`, `http://localhost/*`, `http://127.0.0.1/*`): requested only for the single origin typed under Advanced > API address, at the moment the user saves it, for people who route Gemini or Qwen requests through a relay of their own. Nothing is requested until then, and only that one origin is.

Single purpose: provide audio description of online videos (YouTube, and experimentally Bilibili) for blind and low-vision users.

No remote code: all code ships in the package; the Gemini and Qwen APIs return data (JSON text), not code.

## Data usage disclosure (Chrome Web Store form)

Answers for the *Privacy practices* tab. They say the same as `PRIVACY.md`; when the policy changes, change both.

**Which of the following types of user data does your extension collect?**

- Personally identifiable information: **No.** There are no accounts, and no name, address or email is asked for.
- Health information: **No.**
- Financial and payment information: **No.** The optional SceneVoice Cloud paid tier is handled by a third-party payment platform; the extension never sees card or payment details.
- Authentication information: **Yes, stored locally only.** The user's own API keys (Gemini, Qwen) are kept in `chrome.storage.local` on the user's computer and sent only to the API the user chose, in a request header. They are never sent to the developer. (The SceneVoice Cloud device token, if the user has one, is a random anonymous token issued by the relay at the moment the user presses *Start free* or activates a licence key, not at install; it is stored in `chrome.storage.local`, sent only to `api.scenevoice.app` in a request header, and is the credential that spends the Cloud allowance. It is the one credential that does reach the developer's relay; it is tied to no account, and *Stop using Cloud* removes it.)
- Personal communications: **No.**
- Location: **No.**
- Web history: **No.** The address of the video being described goes to the model in that request only; nothing is logged.
- User activity: **No.** No clicks, keystrokes or usage statistics are recorded.
- Website content: **Yes, as the user's request.** To describe a video the extension sends to the model the user picked: the video's address (Gemini opens the public video itself), its title, channel or uploader and description as shown on the page, the section or moment to describe, the user's typed question and the context listed in `PRIVACY.md`, and, for Qwen or on Bilibili, scaled-down pictures of the playing video. This happens only when the user presses the shortcut or button; nothing is read from pages the user does not describe.

**Who receives this data?** The model API the user chose, under its own terms: Google (Gemini API, `generativelanguage.googleapis.com`) or Alibaba Cloud Model Studio (Qwen, `dashscope.aliyuncs.com`); or, if the user picked SceneVoice Cloud, the optional relay, which forwards the same request to the model with a device token instead of a key and keeps only a daily count per token and, when sharing is on, finished description text. The developer has no server on the bring-your-own-key path and receives nothing.

- I do not use or transfer user data for purposes that are unrelated to my item's single purpose. — True.
- I do not use or transfer user data to determine creditworthiness or for lending purposes. — True.

## Reviewer walkthrough (notes for the review team)

SceneVoice needs an API key of the reviewer's own, or the SceneVoice Cloud free allowance, because it has no server that holds keys.

1. Install: the welcome page opens by itself (focus on its heading). Choose *My own key* there and the settings page opens at the key field (otherwise the toolbar icon > *Settings*).
2. Either paste a Gemini API key (free at https://aistudio.google.com/apikey) under *Gemini* and press *Save and test* — the status line says "Connected" and names the model — or choose SceneVoice Cloud on the welcome page.
3. Open any public YouTube video with speech, for example a cooking tutorial, and press **Alt+Shift+D**. Within about 30 seconds the page announces that descriptions are being created, then "You can start watching"; descriptions are read in the pauses by the screen reader (or the built-in voice, if chosen on the settings page under *Output*).
4. Press **Alt+Shift+S** to describe the current moment, **Alt+Shift+Q** to ask a question about it, **Alt+Shift+L** to repeat the last description.
5. The toolbar popup shows status, progress and the settings; everything works from the keyboard.
6. Bilibili (optional): with a Qwen key saved under *Qwen*, open `https://www.bilibili.com/video/BV…` and press Alt+Shift+D; descriptions come from pictures of the playing video and are a few seconds behind.

On the own-key path no request is made before the user presses a shortcut or button, and all network traffic, visible in the service worker's network panel, goes to the chosen model API (and YouTube's own caption file on YouTube). With SceneVoice Cloud set up, `api.scenevoice.app` is also contacted when the settings page opens (the plan and today's allowance, `GET /v1/me`) and, when descriptions start, for the shared description cache (`GET`, and `PUT` while sharing is on); the description requests themselves go to the relay instead of the model API.
