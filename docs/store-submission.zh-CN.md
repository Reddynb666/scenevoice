# 上架清单：Chrome 应用商店和 Edge 加载项

这份清单是写给项目所有者的，按先后顺序排列：每一步用到的东西，前面的步骤都已经备好。目标是：扩展先以“不公开”的方式上架两家商店，让国内的视障测试者凭链接直接安装，测完再公开。

每一步都有标记：

- 【你来做】只有你本人能做：注册账号、付款、做决定、在后台点按钮、推送代码。
- 【已备好】仓库里已经准备好，照着抄或照着运行就行，后面写了从哪个文件抄。

后台界面上的英文字样是按两家商店的官方文档写的，实际页面可能略有出入。凡是没能核实的事，都列在最后一节；那一节里没有任何“提交之前必须做”的事，那些都写在各自的步骤里。

---

## 第 0 步 【已备好】域名：scenevoice.app 不是项目的，已经从代码和文档里拿掉

这一步你现在不用做任何事，读一遍就行。

查清的事实：scenevoice.app 这个域名不是项目的，也不在你名下。它在 2026 年 7 月 13 日通过 Namecheap 被别人注册了，注册人不明。而 11 月 4 日发布的 1.1.0 版，以及合并这次改动之前线上的网页播放器，都有一个“免费开始”（SceneVoice 云端），它把请求发往这个域名下的一个地址。2026 年 11 月 16 日发现这件事时，那个地址没有解析记录，按了只会失败，也没有发现任何请求被应答过。

为什么要紧，用大白话说：域名在谁手里，谁就可以让那个地址通到自己的服务器。那样的话，

1. 用户在 1.1.0 版里按“免费开始”，扩展会向那台服务器要一个凭证，对方给了，扩展就会相信它。
2. 之后这位用户看的视频地址、标题、输入的问题，在哔哩哔哩上还有画面截图，都会发到那台服务器。
3. 那台服务器返回什么文字，读屏就会把它当成“口述”读给视障用户听。用户看不见画面，没法知道听到的话是不是真的。

已经做了什么：

1. 代码里的中转地址换成了一个永远解析不了的占位地址（以 .invalid 结尾，这是专门保留给“不存在的地址”用的）。总开关关着的时候，构建脚本只认这个占位地址，写别的就打不出包。
2. 十四种语言的界面文字、设置页、两份隐私政策、两份 README、两个网站首页、上架文案里，都不再出现那个地址；说到中转，只说“SceneVoice 云端的中转”，并写明它现在还没有地址。
3. 中转自己的配置 `server/wrangler.toml` 里，原来把那个地址写成线路，还把那个域名下的网站列为“允许调用中转的来源”。照原样部署的话，别人的网站就能调用我们的中转。现在两处都换成了占位，并写明要由运营者填上自己持有的域名。
4. `SECURITY.md` 和 `CHANGELOG.md` 里各有一段说明：发生了什么，装了 1.1.0 的人该怎么办，修好的版本做了什么。
5. 加了一条测试 `test/no-foreign-domain.test.js`。以后谁再把这个域名写进代码、网站或文档，`npm test` 就会失败。

和 1.1.0 有关、还要你动手的事有两件，都排在第 1 步，到时再做：合并，让线上的网页播放器去掉云端选项；合并之后马上撤下 1.1.0 的压缩包，并告诉已经装了的人。这两件都不用等 1.2.0。

域名本身，你以后只有一件事要做，而且只在准备开放 SceneVoice 云端时才需要：先选一个域名，由你本人注册到手，再把它写进代码。注册成功、能在你自己的注册商账号里查到之后，它才算是你的；自动续费要打开。在那之前，云端不能开放，总开关不能打开。

## 第 1 步 【你来做】尽快把这次的改动合并进 main

这一步不用等邮箱、账号和密钥，越早越好：合并之前，线上的网页播放器还带着云端选项。

1. 把这个分支上的改动合并进 main：开一个 PR，等 CI 变绿，再合并。电影应用的代码不会进扩展的包；它要不要跟着进 main，由你决定。
2. 合并之后，GitHub 会自动重新发布网站和网页播放器，一般几分钟。等它变绿。
3. 打开 https://reddynb666.github.io/scenevoice/play/?lang=zh-CN 确认一下：第 2 节里只有 Gemini 密钥的输入框，没有“SceneVoice 云端”这个选项。
4. 在 GitHub 仓库的 Settings 里，找到 Security 一类的页面，打开 Private vulnerability reporting。`SECURITY.md` 现在请别人用它私下报告安全问题；不打开的话，那个报告链接是用不了的。这个开关的确切位置没有核实，以页面为准。
5. 在仓库首页右侧的 About 里，把网站地址填成 https://reddynb666.github.io/scenevoice/ 。
6. 合并之后马上处理 1.1.0，不用等 1.2.0：
   - 在 GitHub 的 Releases 页面编辑 1.1.0 那一条，在说明最前面加一句：这个版本请不要安装，原因见 `SECURITY.md`；修好的版本是 1.2.0，出来之前请先用网页播放器。再把它附带的 `scenevoice-1.1.0.zip` 删掉。
   - 告诉已经装了 1.1.0 的人，包括 AppleVis 上的帖子：在换成新版本之前，不要按“免费开始”，也不要按许可证的“激活”。用压缩包装的扩展不会自动更新，只能靠通知。

网站“安装”一节现在写的是“请安装 1.2.0 或更新的版本，不要安装 1.1.0”，1.2.0 出来之前请读者先用网页播放器。这是为合并之后、1.2.0 发布之前这段时间写的，不用改。

## 第 2 步 【你来做】定一个支持邮箱，把它写进仓库

视障测试者和商店用户需要一个能直接写信的地址。在 GitHub 上提 issue 对他们门槛太高。

最省事的办法：新建一个专门用来发布的 Google 账号，它的邮箱就当支持邮箱，下一步注册 Chrome 开发者账号时也用它登录。不要用私人邮箱：这个地址会公开显示，而且 Chrome 开发者账号的登录邮箱建好之后不能再改。

必须是真实能收信的地址。没有定下来之前，下面这些地方都保持原样，不要填编出来的地址。

定下来以后，开一个 PR，把它写进这些文件（每一处都留了 FILL IN 的注释，搜索 FILL IN 就能找到）：

1. 网站：`site/index.html` 和 `site/zh-CN/index.html`，在“面向机构与创作者”一节，按注释在 GitHub issue 链接前面加一个 mailto 链接。
2. `PRIVACY.md` 和 `PRIVACY.zh-CN.md` 末尾的“联系”一节。
3. `SECURITY.md` 的 Reporting 一节：作为私下报告之外的第二种办法。不想把邮箱用在这里的话，这一处可以不填。
4. 测试指南 `docs/tester-guide.zh-CN.md` 的“怎样参加”一节：准备开始招募时，把“现在还没有开始招募测试者”那两段换成真实的报名办法。还没准备招募，就先不动它。

两个商店后台里也有要填邮箱的地方，到注册和上传的那几步再填，各步里都写了。

## 第 3 步 【你来做】注册两个开发者账号

两个都可以今天开始，互不影响。Chrome 的审核更慢，建议先办它。

### 3.1 Chrome 应用商店开发者账号

开发者后台在中国内地需要代理才能打开：https://chrome.google.com/webstore/devconsole

1. 用第 2 步定下的那个专门用来发布的 Google 账号登录，不要用私人账号。官方的说法是建议用专门的账号，而且开发者账号一旦建好，登录邮箱就不能再改，审核通知都发到这个邮箱。
2. 给这个账号开启两步验证。没有两步验证不能发布，也不能更新。
3. 打开开发者后台，同意开发者协议，支付一次性注册费。
   - 金额：官方页面没有写数字，以后台显示为准；多个非官方来源说是 5 美元。
   - 已知可用的卡：官方没有说明。一般认为要用开通了境外线上支付的 Visa 或 Mastercard，账单地址和卡一致。
   - 已知有问题的：有人公开报告过国内银行的双币 Visa 被拒，错误码 OR-CCSEH-05，所以 Visa、Mastercard 也不保证成功。
   - 不知道的：只有银联标识的卡能不能付，没有找到可靠的说法。
   - 被拒时不要连续重试，换一张卡。
4. 在 Account 页填写发布者名称。它会显示在商店条目的“Offered by”后面，建议写 SceneVoice。
5. 在 Account 页填写并验证联系邮箱。这个邮箱会公开显示在商店条目上，可以和登录邮箱不同；填第 2 步的支持邮箱。
6. 申报是不是 trader（经营者）。这是欧盟《数字服务法》要求的自我申报，所有开发者都要报。现在选 non-trader 说得通：扩展免费、开源，不卖任何东西。将来开始卖 SceneVoice 云端的付费档之前，要改成 trader，到时你的法定姓名、地址和电话会经过验证并公开显示。这是你本人负责的申报，Google 不替你判断。

### 3.2 Microsoft Partner Center（Edge 加载项）

地址：https://partner.microsoft.com/dashboard/microsoftedge/overview

1. 用个人 Microsoft 账号登录。不能用单位或学校的账号。
2. 账号类型选 Individual（个人）。
3. 国家或地区选中国。
4. 第 2、3 两项注册之后都不能改，选之前想清楚。
5. 填发布者显示名，最多 50 个字符，会公开显示，建议和 Chrome 那边一致。
6. 注册免费。

## 第 4 步 【你来做】两把密钥，自己先跑通，切版本之前要定的事

### 4.1 用真实的通义千问密钥，在哔哩哔哩上跑一遍

国内测试者只能走“哔哩哔哩加通义千问”这一条路，而这条路至今只在假页面和模拟模型上测过。发给任何测试者之前，你必须自己先跑通。花费大约几元钱。

1. 用你自己的阿里云账号，在百炼控制台创建一把 API Key。
2. 装上要测的这一版。这时还没有 1.2.0 的包，GitHub 上的 1.1.0 不能装（见第 0 步），所以用源码现做一份：在一个装着最新 main 的文件夹里依次运行 `npm ci` 和 `npm run build`，然后打开 `chrome://extensions`，开启开发者模式，用“加载已解压的扩展程序”选中里面的 `dist` 文件夹。这样装的只给你自己试用，绝不能上传商店，也不能发给测试者。
3. 在设置页的“通义千问 API Key”里粘贴第 1 项的 Key，按“保存并测试”，应该报出模型名。
4. 故意填一把错的，应该听到或看到“通义千问 API Key 无效”。
5. 打开一个真实的哔哩哔哩视频，按 Alt+Shift+D。播放 20 秒左右，应该出现第一条中文口述。
6. 试 Alt+Shift+S 和 Alt+Shift+Q 各一次。
7. 把同一段再看一遍：口述应该按时出现，不再发新的请求。
8. 退出哔哩哔哩登录再试一次，确认不登录也能用。
9. 以上先不开读屏做，确认这条路是通的。然后开着读屏，把 `docs/tester-guide.zh-CN.md` 从第三节到第五节走一遍。测试者用的是 Windows 上的 NVDA、争渡或保益；你手头是 Mac 的话，先用 VoiceOver 加 Chrome 走一遍，有 Windows 机器再补 NVDA。
10. 走的过程中，把浏览器里实际听到的按钮名称，改进测试指南的第三节，开一个 PR 合并。
11. 挑好两个测试视频，记下链接，第 10 步要发给测试者：一个有对白、有停顿的短视频，一个一直有人说话的视频。在中国内地的浏览器里确认不登录也能播放。
12. 哪一步不通，就先修，修好并合并进 main，再做第 5 步切版本；修好之前不要发给测试者。

### 4.2 给审核员准备一把 Gemini 密钥

审核员没有密钥就看不到核心功能，Edge 的审核尤其看重这一点。

1. 新建一个只用于审核的 Google Cloud 项目，在 Google AI Studio 里创建一把 Key。用免费额度，不要绑定付款方式。AI Studio 在中国内地打不开，需要在能访问的网络下申请。
2. 这把 Key 只粘贴到两个后台的审核说明里，绝不写进仓库。
3. 现在只要把 Key 建好。用它把审核说明从头走一遍，要用真正上传的那个压缩包来做，而那个包到第 5 步才有，所以这件事写在第 5 步里。
4. 两家都审核通过后，把这把 Key 删掉（第 9 步会再提醒一次）。

【已备好】审核说明全文在 `docs/store-listing.md` 的“Notes for the reviewer”一节，里面留了一行“FILL IN: PASTE THE REVIEW KEY HERE”给你贴 Key。

### 4.3 切版本之前要定的事

下面这件事会改变包里的内容，所以必须在切 1.2.0 之前定下来：

1. Edge 后台要求包里每一种语言都有一份商店描述，而包里有 16 个语言文件夹，其中 13 个现在没有描述。办法有三个，写在 `docs/store-listing.md` 的“Edge Add-ons”一节。其中“首次提交只打包中英文”要改构建脚本，改完才能切版本。你如果打算先试“在后台把多出来的语言行 Remove 掉”，就什么都不用改，直接做第 5 步；试了不行，再回头改包、切一个新版本。

## 第 5 步 【你来做】切 1.2.0，撤下 1.1.0

要上架的是新切的 1.2.0。不要上传 11 月 4 日发布的 1.1.0，也不要上传任何在自己电脑上打的包。

1. 确认前面几步要进仓库的改动（第 2 步的支持邮箱、第 4 步对测试指南的修改和修掉的问题）都已经合并进 main。
2. 在仓库文件夹之外做一个全新的克隆来切版本。原因是：发布脚本不接受有改动或有未跟踪文件的目录，而平时干活的目录里常常两样都有；全新的克隆里只有 main，最干净。
3. 依次运行：

```
git clone https://github.com/reddynb666/scenevoice.git ~/scenevoice-release
cd ~/scenevoice-release
git switch main
npm ci
npm run release -- 1.2.0
git show HEAD
```

4. `git show HEAD` 里应该只有 CHANGELOG 的 1.2.0 一节，以及 package.json 和 package-lock.json 里的版本号。没问题再推送：

```
git push --follow-tags
```

5. 推送标签后，GitHub 上的发布工作流会自己跑测试、打包，并生成名为“SceneVoice 1.2.0”的 Release。等它变绿。
6. 从 Release 页面下载 `scenevoice-1.2.0.zip` 和 `SHA256SUMS`，放在同一个文件夹里，运行：

```
shasum -a 256 --ignore-missing -c SHA256SUMS
```

   出现 `scenevoice-1.2.0.zip: OK` 才能用。两家商店上传的都是这一个文件。

7. 上传之前，用这个刚校验过的压缩包和第 4.2 步的那把 Key，把给审核员的说明自己走一遍：把压缩包解压到一个新文件夹，在一个全新的浏览器用户配置里用“加载已解压的扩展程序”装上，再照 `docs/store-listing.md` 的“Notes for the reviewer”一节，把那里列的六个步骤从头走到尾。那里写的等待时间是按设计估的；和你实际遇到的不一样，就把 `docs/store-listing.md` 里的那几句改掉，粘贴进后台的也用改过的。走不通就先修，修完重新切一个版本，不要带着走不通的说明去提交。
8. 1.2.0 能正常下载之后，处理 1.1.0：
   - 把第 1 步写在 1.1.0 说明最前面的那句话改成“请改用 1.2.0 或更新的版本”，并给出 1.2.0 的链接。
   - 再告诉一次已经装了 1.1.0 的人，包括 AppleVis 上的帖子：1.2.0 出来了，请换上。
   - 之后可以把网站“安装”一节的提醒改短：两个首页文件开头的说明第 7 条写了怎么改。这句提醒有测试看着，要和测试在同一次提交里改：`site/site.test.js` 里 “version 1.1.0 is not to be installed” 这一条。

【已备好】发布脚本、发布工作流和详细说明：`docs/release.md`。首次上架不需要设置任何自动上传的密钥。

## 第 6 步 【你来做】重新生成截图和徽标

仓库里现有的截图是 11 月 16 日用切版本之前的源码生成的：中英文各六张截图和一张宣传小图。上传用的图要用 1.2.0 的包重新生成一遍，免得图片比包旧。图片不在扩展的包里，所以可以在切完版本之后再做。在第 5 步那个克隆里运行（需要先装好 Python 的 playwright 和 pillow，并运行过 `playwright install chromium`）：

```
npm run build
npm run screenshots
python3 scripts/screenshots.py zh_CN
python3 -c "import runpy; runpy.run_path('scripts/make_icons.py')['draw'](300).save('docs/store/logo-300.png')"
git checkout -- static/icons
```

做完请检查：

1. 每张图都打开看一遍。给 Edge 用的图里不能出现别的浏览器的名字。
2. 图上的字（弹出面板旁边的标语、宣传小图）写在 `scripts/screenshots.py` 的 `WORDS` 里，中英文各一套。宣传小图上不应该有“Any”这个词；中文那一套要用带中文字形的字体，脚本在 Mac 上会自己找到。
3. 脚本生成的图里，没有一张是扩展在视频上工作的样子：进度框、视频上的大字、提问对话框都要真实的视频页才有，弹出面板那张也是“请打开视频”、按钮发灰的状态。请在一个真实视频上手工截一张 1280×800 的图，替换其中一张。
4. Chrome 最多收 5 张截图，六张里要留一张不传；Edge 可以六张都传。
5. 新图片记得提交回仓库：开一个 PR 合并进 main。

【已备好】截图脚本，以及现有哪些图、怎样重做：`docs/store-listing.md` 的“Screenshots”一节。

## 第 7 步 【你来做】Chrome 应用商店：第一次手动上传，设为 Unlisted

第一个版本只能在后台手动创建，接口不能新建条目。

1. 在开发者后台点 Add new item，上传 `scenevoice-1.2.0.zip`。
2. Store listing 页：
   - 语言选 English，粘贴英文描述；再选中文（简体），粘贴中文描述。【已备好】`docs/store-listing.md` 的“Description”一节。
   - 名称和摘要不用填，商店直接读包里的文字。
   - Category 选 Accessibility。
   - 上传商店图标 `static/icons/icon128.png`、截图（最少 1 张，最多 5 张）和宣传小图 `docs/store/promo-440x280.png`。中文（简体）那一栏用 `docs/store/zh-CN/` 里的那一套。

3. Privacy 页：单一用途、每项权限的理由、“不使用远程代码”、数据使用的勾选和三项声明、隐私政策地址。【已备好】`docs/store-listing.md` 的“Single purpose”“Permission justifications”“Data usage disclosure”三节，逐项照抄。

## 第 9 步 【你来做】等审核，不催，也不向别人承诺日期

- Chrome：官方说多数几天内完成，也可能长达几周。按一到三周来安排。超过三周还没结果，可以联系开发者支持。
- Edge：官方说最长七个工作日。
- 第一次审核很可能偏慢，原因有三个：你是新开发者；这是一个新扩展；包里声明了范围很宽的可选主机权限（`https://*/*`，只在用户填自定义 API 地址时才会申请）。官方明确说前两点和“宽泛的主机权限”会让审核更久；可选权限算不算在内，官方没有说。
- 不要向测试者承诺具体的上架日期。
- 被打回时，后台和邮件里会写明原因。把原文保存下来，对照 `docs/store-listing.md` 逐条改，改完再提交。
- 两家都通过之后，把第 4.2 步那把审核用的 Key 删掉。
